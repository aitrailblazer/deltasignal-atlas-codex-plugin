Context And Payload Hygiene

The compact audit artifacts are useful for smoke validation, but duplicate summaries and compact-only payloads should not be treated as independent raw evidence. The client and report renderer should preserve that boundary visibly.

Duplicate artifact control When ContextSHA256 matches, retain one canonical artifact summary and store duplicate filenames as provenance aliases. Preserve timing variance only when comparing performance.
Contract vs live proof OpenAPI confirms route availability and schema intent. MCP/live probes confirm workflow execution for tested paths. Raw issuer correctness still requires targeted evidence drilldowns.
Compact payload disclosure Compact responses should render as compact evidence, not full raw evidence. Cards should say when raw evidence is not attached and when a targeted drilldown is required.
Machine-path preservation Extraction and rendering layers must not mutate field paths such as result.structuredContent.data, computed_at_utc, or source_date.

Canonical Dedupe Rule

1. ContextSHA256 wins first:
   same ContextSHA256 = same logical payload.
   keep one canonical chip; preserve ArtifactSHA256 aliases.

2. ArtifactSHA256 catches stored-byte duplicates:
   same ArtifactSHA256 with different wrappers = same stored artifact.
   keep the richer wrapper; preserve the other wrappers as references.

3. route_contract_hash_v1 handles semantic OpenAPI identity:
   dedupe route-contract subdocuments, not live audit chips.
   live audit chips may carry distinct source dates, timings, and status.

Contract Hash Canonicalization

route_contract_hash_v1 hashes interface, not prose:
extract method, path, operation_id, parameters, request_body,
responses, and payment metadata when the payment hash is not split

drop descriptions, summaries, examples, live response data,
issuer data, runtime x402 challenge headers, elapsed times,
source dates, wrapper metadata, filenames, and formatting

normalize: lowercase method, preserve OpenAPI path template,
sort parameters by in/name, sort response codes numerically,
use amount_usd strings, omit readiness "_" placeholder,
then SHA256(canonical_json_utf8)
interface_hash Detects breaking or behavioral route drift. Include OpenAPI identity, server, path names, HTTP methods, operation IDs, parameters, request bodies, response status codes, response schemas, components schemas, and request-shaping security schemes. Exclude prose, examples, and x_payment_info.
payment_hash Detects x402, chain, asset, route-price, and payment-policy drift. Include route path and method plus x_payment_info, protocol blocks, amountUsd, currency, asset, network, chain ID, facilitator, scheme, auth mode, payment methods, and price fields.
documentation_hash Detects docs and discoverability drift without marking interface or payment changes. Include info descriptions, route summaries/descriptions, parameter and response descriptions, schema descriptions, tags, caveats, natural-language endpoint notes, and Base x402 versus MPP compatibility notes.
Hash boundary The attached four-route projection is computable. Full production interface_hash, payment_hash, and documentation_hash for all 43 routes require raw /openapi.json, not only artifact/context hashes.
